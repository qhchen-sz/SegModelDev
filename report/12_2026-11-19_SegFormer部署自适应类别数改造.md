# SegFormer 部署自适应类别数改造（兼容任意输出类别的分割引擎）

> 对应 commit `4b8f365`（2026-11-19，"修改部署代码，支持不同输出的segformer模型"）。
> 涉及 `deploy_cpp/segformer_dll/`（30 系，TRT8.6）、`deploy_cpp/segformer_dll50/`（50 系，TRT10.10）、
> 强制同步副本 `deploy_cpp/src/`、两系 C# 工程 `deploy_cpp/EVDll_Segformer{,50}/` 及 `deploy_cpp/README.md`。

---

## 0. 结论速览

- 改造后，同一套 `segformer_Dll_func.dll` + `EVDll_Segformer.dll` 兼容**任意类别数**的 SegFormer 引擎
  （实测 2 / 3 / 5 类），换模型只需换 `.engine` 文件，无需重编 DLL——与 YOLO 部署的用法对齐。
- 改动伴随 **C ABI 变更**：`SegStat` 结构体从 1840 字节缩到 **1800 字节**（`px[3]/ncomp[3]` 移出），
  新增 `SegGetNumClasses()`，`SegGetStat()` 改变长数组参数。
  **C# 组件与 C++ DLL 必须同批替换**，混用会导致封送错乱。
- 叠加图配色从"撕裂红 / 翻折蓝"改为 **YOLO 80 色调色板**（`label % 80` 循环取色，任意类别数不越界），
  背景保持灰色 (60,60,60)。

## 1. 背景与动机

### 1.1 直接动机：焊线 2 类模型上线

新训练的焊线检测模型（`SceneTest/mszhc5/export/segformer_hanxian_b1_fp16_640.engine`）是
**2 类**（背景 + 焊线），而部署工程里类别数是硬编码的 3：

- `SegConfig.numClasses = 3`（0=背景 / 1=silie 撕裂 / 2=fanzhe 翻折）；
- argmax / softmax 按 3 类手写三段展开；
- `SegStat` 里 `px[3]/ncomp[3]` 定长数组；
- C# 示例脚本写死 `st.px[1]=撕裂`、`st.px[2]=翻折`。

2 类引擎输出 logits 为 `1x2x160x160`，旧校验 `od[1] != numClasses` 直接拒绝加载。
要让焊线模型上线，必须把"类别数"与代码解耦。

### 1.2 排查过程中确认的关联问题（本次未改代码，仅记录）

排查"加 softmax 阈值后结果与之前差很多"的过程中，顺带确认了两个问题：

1. **二分类下阈值 0.5 等价纯 argmax**：置信度过滤的规则是"softmax 最大概率 < 阈值 判背景"。
   n 类时最大概率恒 ≥ 1/n，2 类时恒 ≥ 0.5，所以阈值 0.0 / 0.5 都不产生任何过滤。
   "阈值 0 与不加 softmax 差很多 + 出现误检"的真正原因是：测试时 B 工程的 `SegLoad`
   静默失败，跑的仍是 A 模型（见下条），与 softmax 本身无关。2 类模型要压假阳，阈值须设 **> 0.5**。
2. **`AI_Seg1.Init` 的静默返回**：C# 静态槽 `Init` 里有 `if (_model != null) return;`，
   同一软件进程先加载 A 工程、再加载 B 工程时，B 的加载请求被静默忽略，一直在跑 A 模型
   （之前"30 显卡和 50 显卡结果不一致"报警的另一根因是目标机 DLL 未更新，二者叠加）。
   这是"一槽一模型"的设计：多工程共驻时必须用不同槽位（`AI_Seg1~47`），
   或改用实例式 `SegModel`。

## 2. 方案设计：借鉴 YOLO 部署的三条原则

YOLO 的 C++ 部署（`D:\CaoJiaoJie\gpu_All_Dll_func`）能用同一 DLL 兼容不同 YOLO 模型，核心做法：

| YOLO 做法 | 本次 SegFormer 对应 |
|---|---|
| 类别数从引擎张量维度读，不写死 | init 时读输出 dims `od[1]`，仅要求 ≥2，不设上限 |
| 类别语义（类名/颜色）不进推理链路，由脚本解释 | `boxCls` 只报类别 id；示例脚本不再写死 silie/fanzhe |
| 阈值运行时化 | 沿用上一轮的 `SegSetConfidenceThreshold`（不改） |

调色板颜色按用户确认直接采用 YOLO 的 80 色 COLORS，不再沿用"前两个色 = 红/蓝"的旧习惯。

## 3. C++ 改动明细

30 系 `deploy_cpp/segformer_dll/`（及同步副本 `deploy_cpp/src/`）与
50 系 `deploy_cpp/segformer_dll50/` 同构修改。

### 3.1 类别数自适应（`seg_pipeline.hpp` / `seg_pipeline.cpp`）

- `SegConfig.numClasses` 改为 init 时用引擎输出通道数 `od[1]` 覆盖；
  校验从 `od[1] != numClasses`（严格相等）放宽为 `od[1] < 2` 报错。
- argmax / softmax 的三段展开（v0/v1/v2 手写比较）泛化为 `numClasses` 循环：

```cpp
const int nc = cfg_.numClasses;
// argmax
float bv = -std::numeric_limits<float>::max();
for (int c = 0; c < nc; ++c) {
    const float v = a[c][x] * invCov;
    if (v > bv) { bv = v; best = c; }
}
// softmax 分母（减最大值防溢出，数学形式不变）
float denom = 0.0f;
for (int c = 0; c < nc; ++c) denom += std::exp(a[c][x] * invCov - bv);
```

即：原始滑窗 logits 逐通道累加 → 按覆盖次数归一 → argmax 定标签 → softmax（减最大值）算置信度 →
阈值过滤。除"类数从 3 泛化到 N"外，数值路径与改造前完全一致。

### 3.2 `SegStat` ABI 变更（`segformer_dll.h`）

- `SegStat` 移出 `px[3]/ncomp[3]`，只留与类别数无关的定长字段
  （`ng / nbox / boxCls[64] / boxX / boxY / boxW / boxH / boxPx[64]`），`sizeof` **1840 → 1800**。
- 新增 `SEG_API int SegGetNumClasses(void* model)`：`SegLoad` 成功后可用，未加载返回 0。
- `SegGetStat` 改变长数组参数：
  `SegGetStat(model, out, px, pxCap, ncomp, ncompCap)`，按容量填 `min(cap, 类别数)` 项，
  传 `nullptr` 只取定长部分。**按类别统计不进结构体，类别数变化不再影响 ABI**
  （与 YOLO 部署 `ResultPara` 的设计一致）。

### 3.3 overlay 换 YOLO 调色板（`seg_pipeline.cpp` / `seg_pipeline.hpp`）

- 新增 `cv::Scalar segClassColor(int label)`：`label<=0` 为背景灰 (60,60,60)；
  前景类取 YOLO 调色板第 `label % 80` 色（`kColors[80][3]` 与
  `gpu_All_Dll_func\infer.cpp` 的 COLORS 逐字节同源），任意类别数不越界。
- `segOverlay` 原写死的 `cols[3] = {灰, 红, 蓝}` 改为 `segClassColor(lab[x])`；
  alpha=0.5 混合约定不变（对背景也混合、整图压暗的效果保留，与 Python 参考实现对齐）。

## 4. C# 改动明细（两系 `EVDll_Segformer` / `EVDll_Segformer50`）

- **封送结构拆分**：原 `SegStat` 结构体拆为两部分——
  - `SegStatNative`：定长，字段顺序/类型与 C++ 逐字节一致，专走 P/Invoke；
  - `SegStat`（托管类）：`px/ncomp` 为变长数组，`GetStat` 时先查 `SegGetNumClasses`
    分配对应长度再取数。
- **新包装**：`AI_Seg1.NumClasses()`；`AI_Seg_Slots.cs` 的 47 个槽（`AI_Seg1~47`）×
  各 API 重载全部同步。
- **50 系诊断功能保留**：50 系 C# 特有的 `SegTrace` 埋点、`SegFrameTiming` 结构、
  `SegGetLastTiming / SegTimingSize / SegProfileConfigure / GetCurrentThreadId`、
  `GetStat` 内的计时埋点均保留（本次曾因整文件覆盖误删，已恢复并逐段核对，
  50 系相对 30 系的 diff 为 +109/−15，11 处 50 系特有引用 grep 确认齐全）。
- **示例与自测同步**：`SoftwareScriptSample.cs`、`SegTest/Program.cs` 的统计输出
  从写死 `px[bg=.. silie=.. fanzhe=..]` 改为按 `st.px.Length` 循环；
  斑点分析示例注释改为"0=背景，1..N=前景类，含义由模型 id2label 决定"。
- **部署警告**：C# 注释与两系 README 均注明"本 DLL 与 `segformer_Dll_func.dll`
  必须同批替换（GetStat ABI 已变更）"。

## 6. 迁移注意事项（旧工程升级必看）

1. **C# 与 C++ DLL 必须同批替换**：`SegStatSize()` 从 1840 变 1800，
   旧 C# + 新 DLL（或反之）封送直接错乱。
2. **旧脚本写死 `st.px[2]` 会越界**：2 类模型 `px.Length=2`，访问 `px[2]` 抛
   `IndexOutOfRangeException`。须按 `AI_Seg1.NumClasses()` 改写循环。
3. **叠加图颜色变了**：类别 1 不再是红、类别 2 不再是蓝，改为 YOLO 调色板
  （与 YOLO 部署输出颜色一致）。下游若用颜色区分缺陷类别，应改为读 `boxCls/label`。
4. **二分类阈值**：0.5 = 纯 argmax（不过滤）；压假阳需设 > 0.5。
